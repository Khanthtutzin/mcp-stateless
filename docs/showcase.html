mcp-stateless · demo

Is your MCP server actually ready?

mcp-stateless checks the server you are actually running against the MCP 2026-07-28 stateless specification.

$ npx mcp-stateless --stdio "node dist/server.js"
01 · the idea

It tests the server, not the source code.

Your MCP serverReal runtime behaviour
→
mcp-statelessProbe + evaluate
→
VerdictReady / findings

A version number or successful build is not enough. The checker communicates with the running server and uses the responses as evidence.

02 · how it checks

One small, controlled conversation.

01
DiscoverAsk server/discover what the server supports.
02
ProbeCheck protocol behaviour such as listings, headers and the old handshake.
03
ObserveRecord the actual responses, headers and error codes.
04
EvaluateRun the 18 rules against the shared probe results.
05
ExplainShow what was found, what was expected and who needs to fix it.
03 · demo

Old server → clear evidence.

    expected  server/discover must be implemented.
    fix       Upgrade to an SDK release targeting 2026-07-28.

× MCP006  Removed ping method is still implemented (SDK)

NOT READY — 7 breaking issues
04 · the useful part

It tells you who owns the fix.

SDK

Protocol plumbing supplied by the MCP SDK. Often fixed by upgrading the dependency.

LESS CODE TO CHANGE
YOUR CODE

Behaviour your application actually controls. The report points to the concrete change.

ACTIONABLE FINDING

Seven findings do not necessarily mean seven code changes.

05 · confidence

When it cannot measure, it does not guess.

unreachable server
UNREACHABLE — Server process exited before responding.

No checks were run.
Nothing here is a verdict on conformance.

No invented failures. No fake “ready”. The tool reports only what it actually observed.

06 · try it

Point it at a server you own.

$ npx mcp-stateless --stdio "node dist/server.js"
$ npx mcp-stateless --http https://api.example.com/mcp

It supports CLI, library use and GitHub Actions. It never calls your MCP tools and has no telemetry.
